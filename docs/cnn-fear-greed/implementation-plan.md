# CrossETF 恐惧贪婪指数正式实施方案

## 1. 文档状态

- 日期：2026-10-19
- 阶段：最终方案
- 状态：已执行并通过验收
- 依据：`requirements-analysis.md`、`discussion-notes.md`、`demo.html`、`design-qa.md`
- 目标版本：`v1.5.0`
- 本文件是本需求唯一执行依据；如后续讨论改变关键口径，应先更新本文件再修改业务代码。

## 2. 已确认方案摘要

在 CrossETF 顶部四张宏观卡下方增加独立的“恐惧贪婪指数”模块，用于查看美国股票市场当前情绪和最近 30 个自然日的日级趋势。

核心边界：

- 只接入 CNN 口径的恐惧贪婪指数，不接入 VIX。
- 模块与 ETF 业务完全隔离。
- 不参与 ETF 估值、溢价率、排序、评级、换仓测算或历史归档。
- 使用独立接口、独立外部抓取、独立内存缓存和独立持久化缓存。
- 上游或情绪接口故障不得阻塞 `/api/quotes`，也不得影响页面其他功能。
- 正式前端按照已经确认的 `demo.html` 紧凑双栏方案实现。
- 不展示七项组成指标、离散历史对比值或长期历史图表。

## 3. 总体架构

```text
FearGreedFlow 公开 JSON
        │
        │ 最多每 60 分钟抓取一次
        ▼
server.py 独立抓取、校验与标准化
        │
        ├── 内存缓存（正常 60 分钟）
        ├── 失败重试节流（10 分钟）
        └── data/fear_greed_cache.json（最后有效数据）
        │
        ▼
GET /api/fear-greed
        │
        ▼
static/index.html 独立 Vue 状态与 Canvas 趋势图
```

禁止的数据流：

```text
/api/quotes ──X──> FearGreedFlow
CNN 指数 ──X──> ETF 估值或溢价计算
CNN 指数 ──X──> history_daily.json
```

## 4. 数据源方案

### 4.1 正式主源

- 名称：FearGreedFlow 公开 JSON。
- 地址：`https://feargreedflow.com/api/fear-greed`。
- 认证：不需要 API Key。
- 当前结构：`dates`、`values`、`asOf`、`indicators`。
- 本需求只读取 `dates`、`values` 和 `asOf`。
- 上游声明：每小时刷新。

### 4.2 不采用双在线源

第一版不把 CNN 内部端点作为自动备用源：

- CNN 端点不是正式公开 API。
- 2026-10-19 实测普通程序请求返回 HTTP 418。
- 双源会增加字段映射、口径比对和故障判断复杂度，却不能提供可靠的独立冗余。

本项目的降级来源是“最后一次有效持久化数据”，而不是另一个不稳定在线端点。

### 4.3 后续替换能力

外部字段只允许在后端适配层出现。前端只消费 CrossETF 标准结构，因此未来切换认证 API 或其他数据源时不改组件结构。

## 5. 数据校验与标准化

### 5.1 原始结构校验

一次响应必须同时满足：

- 根对象是 JSON object。
- `dates` 和 `values` 均为数组。
- 两个数组长度相同且非空。
- 日期能够解析为 `YYYY-MM-DD`。
- 分数能够转换为有限数值且位于 `0～100`。
- `asOf` 能解析为有效时间；缺失时允许使用最后一个有效日期，但不得伪造为当前时间。

无效项目逐项丢弃；过滤后没有有效数据则整次抓取失败，不覆盖旧缓存。

### 5.2 当前值

- 将有效日期与数值配对后按日期升序排列。
- 最后一项作为当前值。
- 后端保留一位小数，例如 `17.9`。
- 前端主数字使用四舍五入后的整数，例如显示 `18`。
- 情绪等级按未取整的原始值判定。

### 5.3 情绪等级

采用唯一、无重叠区间：

| 数值范围 | 代码 | 中文 |
|---|---|---|
| `< 25` | `extreme_fear` | 极度恐惧 |
| `25～<45` | `fear` | 恐惧 |
| `45～<55` | `neutral` | 中性 |
| `55～<75` | `greed` | 贪婪 |
| `75～100` | `extreme_greed` | 极度贪婪 |

### 5.4 最近 30 个自然日

- 以数据源最后一个有效日期为基准，而不是以服务器当天时间为基准。
- 保留该日期及向前 29 个自然日内的所有有效日级数据。
- 周末和休市日不补零、不插值。
- 返回结果保持日期升序。
- 不读取或展示七项组成指标。

## 6. 独立 API 设计

### 6.1 路由

```http
GET /api/fear-greed
```

不提供强制刷新参数或公开刷新接口，避免绕过上游节流。

### 6.2 正常或缓存降级响应

正常数据和最后有效缓存均返回 HTTP 200；调用方通过 `stale` 和 `status` 区分。

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "valid": true,
    "status": "fresh",
    "stale": false,
    "source": "feargreedflow",
    "score": 17.9,
    "rating": "extreme_fear",
    "rating_label": "极度恐惧",
    "as_of": "2026-10-16T23:59:49+00:00",
    "last_success_at": "2026-10-19T01:30:00+08:00",
    "history": [
      {"date": "2026-09-17", "value": 46.2},
      {"date": "2026-10-16", "value": 17.9}
    ]
  }
}
```

降级时仅改变：

```json
{
  "status": "stale",
  "stale": true
}
```

必须继续保留原始 `as_of` 和 `last_success_at`，不能把失败时间冒充成数据更新时间。

### 6.3 首次启动且无缓存

如果外部抓取失败且本地从未保存过有效数据：

- 返回 HTTP 503。
- `code` 为 `503`。
- `data.valid` 为 `false`。
- `score` 和 `history` 不返回虚假默认值。
- 前端显示“情绪数据暂不可用”，不影响其他模块。

### 6.4 HTTP 头

- `Content-Type: application/json; charset=utf-8`
- `Cache-Control: no-cache, no-store, must-revalidate`
- 延续现有接口的 CORS 策略。

浏览器缓存关闭不代表没有后端业务缓存；业务缓存由服务器按本方案统一管理。

## 7. 缓存与失败状态机

### 7.1 参数

- 成功缓存周期：`3600` 秒。
- 失败重试间隔：`600` 秒。
- 外部请求超时：建议 `8` 秒。
- 持久化文件：`data/fear_greed_cache.json`。

### 7.2 请求流程

每次访问 `/api/fear-greed`：

1. 存在成功缓存且距上次成功抓取不足 60 分钟：直接返回缓存，`stale: false`。
2. 缓存已到期，且距上次失败尝试不足 10 分钟：返回最后有效数据，`stale: true`，不重复访问上游。
3. 缓存到期且允许重试：尝试抓取上游。
4. 抓取、解析和校验成功：更新内存与持久化缓存，返回 `fresh`。
5. 抓取失败但存在最后有效数据：返回最后有效数据，标记 `stale`。
6. 抓取失败且没有任何有效缓存：返回 HTTP 503。

只要上游重新成功，立即退出 `stale` 状态并恢复 60 分钟正常周期。

### 7.3 并发控制

`ThreadingHTTPServer` 可能同时收到多个到期请求，因此必须为情绪刷新增加独立 `threading.Lock`：

- 同一时刻只允许一个线程访问外部源。
- 进入锁后再次检查缓存，避免重复抓取。
- 锁只保护情绪模块，不复用 ETF 行情缓存锁。

### 7.4 持久化规则

- 只持久化已经标准化并通过校验的数据。
- 采用临时文件写入后 `os.replace` 原子替换。
- 读取失败、JSON 损坏或版本不兼容时忽略该文件并尝试在线抓取。
- 抓取失败绝不覆盖最后有效文件。
- 运行时缓存文件加入 `.gitignore`，不提交真实运行数据。
- 不修改已有 `data/nasdaq_symbols_cache.json` 和 `data/history_daily.json`。

## 8. 后端实现范围

正式修改集中在 `server.py`：

### 8.1 新增配置

- `FEAR_GREED_URL`
- `FEAR_GREED_CACHE_TTL = 3600`
- `FEAR_GREED_RETRY_TTL = 600`
- `FEAR_GREED_TIMEOUT = 8`
- `FEAR_GREED_CACHE_FILE`

### 8.2 新增独立状态

建议独立对象保存：

- 标准化后的最后有效 payload。
- 上次成功抓取时间。
- 上次尝试时间。
- 最近错误摘要。
- 是否已经读取持久化缓存。
- 独立刷新锁。

不得复用 `cache_data`；后者只属于 `/api/quotes` 的 3 秒行情缓存。

### 8.3 新增函数职责

- `classify_fear_greed(score)`：唯一等级映射。
- `normalize_fear_greed_payload(raw)`：校验、配对、排序和截取 30 日。
- `load_fear_greed_cache()`：读取并验证持久化缓存。
- `save_fear_greed_cache(payload)`：原子写入。
- `fetch_fear_greed_upstream()`：只负责外部请求和 JSON 解码。
- `get_fear_greed_data()`：执行缓存状态机。

函数名允许按现有代码风格微调，但职责不能重新混入 `get_market_data()`。

### 8.4 新增路由

在 `DashboardHandler.do_GET()` 中增加 `/api/fear-greed` 分支，位置与 `/api/quotes` 平级。

禁止：

- 在 `get_market_data()` 内调用情绪源。
- 将情绪对象塞入 `/api/quotes` 的 `macro`。
- 因情绪异常清空或穿透 ETF 行情缓存。

## 9. 前端正式实现

正式修改集中在 `static/index.html`。

### 9.1 位置

- 保留现有四张宏观卡。
- 情绪模块位于宏观卡下方、ETF 分类 Tab 上方。
- 独立占一整行，不作为第五张宏观小卡。

### 9.2 内容

常驻展示：

- 标题“恐惧贪婪指数”。
- 当前整数分数。
- 中文情绪等级。
- 上游真实更新时间。
- 五段色温条和当前指针。
- 最近 30 个自然日趋势线。
- `stale` 时轻量显示“缓存数据”。

不常驻展示：

- 七项组成指标。
- 前收盘、一周前、一个月前、一年前等离散数字。
- 大段市场解释。
- 数据源技术细节。

### 9.3 通俗解释

悬浮、点击或键盘聚焦情绪等级时显示：

> 当前市场更偏向避险：买入和追涨意愿变弱，卖出压力可能增大；但不等于所有投资者都在不计成本抛售，也不代表市场已经见底。

该提示必须支持：

- 鼠标 hover。
- 键盘 focus。
- 手机轻触。
- 清晰的 `focus-visible` 样式。

### 9.4 色温交互

- 鼠标在色温条移动时显示对应的 `0～100` 数值和情绪区间。
- 提示框在左右边缘自动调整，不能溢出卡片。
- 色温条自身提供可访问性说明。
- 当前值指针与实际分数位置一致。

### 9.5 趋势图

- 使用原生 Canvas，不引入图表库。
- 使用源数据真实比例绘制，不对缺失日期补值。
- 鼠标移动时显示最近数据点的日期和数值。
- 浅色、深色主题分别读取现有颜色变量。
- Canvas 绝对定位在尺寸已确定的 wrapper 内，绘图缓冲区不得反向撑高父容器。
- 重绘前按 CSS 尺寸和 `devicePixelRatio` 设置 backing store，避免模糊。
- 主题切换、数据更新和视口变化后重绘。

### 9.6 响应式布局

按照最终 Demo：

- 桌面端：左栏固定约 `176px`，右侧趋势图占剩余空间。
- 手机端：继续保持紧凑双栏，不把趋势图堆到指数下方。
- 极窄屏幕：缩小数字、标签、间距和图表字号，但仍保持双栏。
- 左右标题顶线和底部标签基线对齐。
- 卡片高度由稳定布局尺寸决定，不允许 Canvas 循环撑高。

### 9.7 Vue 状态和刷新

新增独立状态，例如：

```text
fearGreed: null | normalized object
fearGreedLoading: boolean
fearGreedError: string | null
```

新增 `fetchFearGreed()`：

- 页面挂载时调用一次。
- 前端另设 60 分钟定时器，只请求 `/api/fear-greed`。
- 页面“刷新”按钮可以同时请求两个本地接口，但不能绕过后端情绪缓存。
- 通过 `Promise.allSettled` 或独立 `try/catch` 保证任一接口失败不影响另一个接口状态。
- 组件卸载时清理独立定时器和绘图监听。

### 9.8 异常状态

- `fresh`：正常展示，不额外打扰用户。
- `stale`：继续展示最后有效数据，在更新时间附近增加低干扰“缓存数据”标识。
- `unavailable`：显示“情绪数据暂不可用”，分数使用 `--`，趋势图不绘制；ETF 页面保持正常。
- 不得把缺失数据展示成 `0` 或“极度恐惧”。

## 13. 验收标准

### 数据

- 当前分数来自最新有效数据点，范围为 0～100。
- 中文等级与区间一致。
- 趋势只包含最近 30 个自然日内的有效数据。
- 更新时间来自上游，不伪造为当前时间。

### 缓存

- 成功后 60 分钟内不重复访问上游。
- 到期失败时继续返回最后有效数据。
- 失败后 10 分钟内不重复重试。
- 服务重启后能够读取最后有效缓存。
- 无任何有效数据时明确显示不可用，不显示零分。

### 隔离

- `/api/quotes` JSON 结构和 ETF 计算结果保持不变。
