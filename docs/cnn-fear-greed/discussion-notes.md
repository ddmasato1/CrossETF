## 已确认事项

### D-001 取消 VIX

- 状态：已确认
- 用户意见：平常不会查看 VIX，因此不需要接入 VIX。
- 结果：VIX 不进入本需求，也不在 CrossETF 中新增对应卡片或走势图。

### D-002 仅保留 CNN 恐惧与贪婪指数

- 状态：已确认
- 用户意见：只保留 CNN 恐惧与贪婪指数，用于查看市场情绪和温度。
- 结果：后续方案只围绕 CNN 指数展开。

### D-003 与 ETF 业务隔离

- 状态：已确认
- 指标只用于市场情绪展示，不参与 ETF 估值、溢价、排序或价差测算。

### D-004 不展示七项组成指标和离散历史对比值

- 状态：已确认
- 用户判断：七项组成指标以及前期离散数值即使展示，实际查看价值有限。
- 结果：不默认展示七项组成指标，也不展示前收盘、一周前、一个月前和一年前的独立对比数字。
- 目的：保持看板简洁，避免将情绪温度计扩展为复杂研究工具。

### D-005 只保留当天状态和近期趋势

- 状态：已确认
- 用户目标：关注当天情绪以及最近 7～30 天的变化方向。
- 讨论结论：由于日级历史在 7 个自然日内通常只有约 5 个交易点，默认采用最近 30 个自然日的日级简洁趋势线。
- 展示内容：当前分数、情绪等级、更新时间和近期趋势线。
- 不包含：长期历史分析、复杂指标拆解和多组离散历史值。

### D-006 收紧卡片空间，解释按需显示

- 状态：已确认
- 用户意见：常驻的文字解释区域占用空间过大，应直接删除。
- 结果：情绪卡片只保留当前分数、色温条和最近 30 日趋势两部分。
- 通俗解释改为悬浮、点击或键盘聚焦“极度恐惧”等情绪等级标签时显示；默认不占据布局空间。

### D-007 正式前端采用 Demo 方案

- 状态：已确认
- 用户意见：当前 Demo 效果认可，正式环境前端可以按照该效果实现。
- 结果：正式前端沿用紧凑双栏情绪卡片；左侧显示当前分数、情绪等级、更新时间和色温条，右侧直接显示最近 30 日走势。
- 桌面端和移动端均保持双栏；极窄屏幕缩小字号与图表，但不重新产生大块空白。
- 色温条悬浮显示对应分数及区间；情绪等级悬浮、点击或聚焦显示通俗解释。

### D-008 后端与 ETF 业务完全隔离

- 状态：已确认
- 用户意见：恐惧贪婪指数是独立模块，与 ETF 无关。
- 结果：正式实现采用独立接口、独立抓取和独立缓存，不将外部情绪源调用放入 ETF 行情处理链路。
- CNN 数据不参与 ETF 估值、溢价率、排序、换仓测算或历史归档。
- CNN 数据故障、超时或陈旧时，只影响情绪模块自身，不得影响 `/api/quotes` 和页面其他功能。

### D-009 抓取失败继续显示最后有效数据

- 状态：已确认
- 用户意见：如果当前抓取失败，继续显示最后一次成功数据。
- 结果：不得以 `0`、空数组或错误页面覆盖有效缓存；返回最后有效数据，并保留其真实数据时间。
- 后端同时返回 `stale: true` 和最后成功抓取时间，前端以轻量状态提示这是缓存数据。
- 服务重启后仍需能够读取最后有效数据，因此除内存缓存外保留一个独立持久化缓存文件。

### D-010 正常数据每小时刷新

- 状态：已确认
- 用户意见：上游本身每小时更新，本项目没有必要每 30 分钟重复抓取。
- 结果：成功抓取后的正常缓存周期采用 60 分钟。
- 若刷新失败，继续返回最后有效数据，并采用 10 分钟的失败重试间隔；恢复成功后重新进入 60 分钟正常周期。

## 已知事实

### F-001 指标方向

- 分数范围为 0～100。
- 越低代表越恐惧，越高代表越贪婪。
- 它与 VIX 常呈反向关系，但不是严格数学反函数。

### F-002 数据更新粒度

- CNN 表示各组成指标和综合指数在新数据可用时重新计算，没有固定秒级更新承诺。
- 当前公开接口主要提供当前快照和日级历史，不具备可靠的官方分钟级历史。
- 该指标更适合低频刷新和日线趋势，不需要按期货频率刷新。

### F-003 已验证的数据源

#### CNN 内部端点

- 地址：`https://production.dataviz.cnn.io/index/fearandgreed/graphdata`
- 数据最接近源头，包含当前值、对比值、历史和组成指标。
- 2026-10-19 重新实测：普通程序请求返回 HTTP 418，即使提供基础浏览器 User-Agent 和 Referer 仍可能被识别为机器人。
- 不是有稳定性承诺的正式公开 API。

#### FearGreedFlow 公开镜像

- 新地址：`https://feargreedflow.com/api/fear-greed`
- 旧域名 `https://fearandgreedgraph.com/api/fear-greed` 当前仍可访问；服务已更名为 FearGreedFlow。
- 无需密钥、无需注册、开放 CORS，提供当前分数和日级历史；官方说明为每小时刷新。
- 2026-10-19 实测返回 HTTP 200 和 JSON。
- 属于第三方镜像，没有官方服务保证。

#### FearGreedFlow 认证 API

- 地址：`https://feargreedflow.com/api/v1/fear-greed?history=true`
- 需要 Bearer API Key；免费层当前标注为每日 300 次、最多 90 日历史。
- 优点是结构与限额说明更正式；缺点是需要管理密钥，本需求暂时没有必要。

#### 其他候选

- FearGreedChart 是独立五因子模型，不能标注为 CNN 指数。
- GitHub/jsDelivr 镜像实测已经停更。
- oanor 实际业务端点返回 HTTP 401。
- SentiSense 和 RapidAPI 需要认证或 API Key。

## 最终方案结论

### D-011 五档固定情绪解释

- 状态：已确认
- 五个情绪等级各自使用固定标题和通用解释文案，不合并极端档与普通档。
- 不读取或返回七项组成指标，不根据当前市场变化生成“主要驱动因素”分析。
- 解释仅说明等级的一般含义，不预测后续市场表现，不包含买卖建议。
- 五档文案以 `requirements-analysis.md` 与 `implementation-plan.md` 中的表格为准。

### P-000 视觉 Demo

- 已创建独立静态 Demo，用模拟数据验证现有 CrossETF 视觉体系下的展示效果。
- 已确认布局：保留四张现有宏观卡，CNN 市场情绪模块在其下方独立占一整行。
- 已确认交互：当前分数、温度条和最近 30 日趋势线直接展示，不需要点击展开。
- Demo 是正式前端实现的视觉依据，目前尚未修改业务代码。

### P-001 数据链路

已确认由后端读取数据、校验并缓存，再通过 CrossETF 自身 API 提供给前端，避免浏览器跨域、重复请求和外部结构直接泄漏到页面逻辑。

### P-002 数据源策略

已确认策略：

- 主源：FearGreedFlow 无密钥公开 JSON。
- 不配置不可靠的在线备用源；CNN 内部端点当前返回 HTTP 418。
- 主源失败时：使用最近一次有效缓存并标记陈旧。

第一版采用公开镜像作为唯一在线主源，以最后有效持久化缓存作为故障降级。

### P-003 刷新周期

状态：已确认。

公开数据源声明每小时刷新，因此成功数据的缓存周期采用 60 分钟。这里的“缓存周期”仅表示两次正常外部抓取之间的最短间隔：前端可以随时请求 CrossETF 自身接口，但后端在 60 分钟内直接返回已经验证过的数据；超过 60 分钟后，下一次请求才尝试重新抓取外部源。

刷新失败时不等待完整 60 分钟，采用 10 分钟失败重试间隔；重试期间持续返回最后有效数据并标记 `stale: true`。

### P-004 简洁展示

按照“查看市场情绪和温度”的目标，已确认展示字段为：

- 当前分数。
- 中文情绪等级。
- 更新时间。
- 最近 30 个自然日的日级趋势线。
- 数据陈旧或不可用状态。

不展示七项组成指标、前收盘/一周前/一月前/一年前的离散数值和长期历史图表。

### P-005 独立后端情绪接口

状态：已确认。

结合现有架构，新增独立的 CNN 情绪接口和独立缓存，不让低频外部情绪数据跟随 `/api/quotes` 的高频行情缓存刷新。

- 推荐接口：`GET /api/fear-greed`。
- 返回当前分数、情绪等级、更新时间、最近 30 日数据、有效/陈旧状态和来源。
- 使用独立内存缓存和最近一次有效的持久化缓存。
- 外部情绪源请求失败时不得阻塞或改变 ETF 行情接口。
- 本项属于后端小范围扩展；数据源、缓存参数和接口隔离均已写入最终实施方案。
