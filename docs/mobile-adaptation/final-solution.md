# CrossETF 移动端适配最终实施方案

## 1. 文档状态

- 日期：2026-10-18
- 阶段：实施完成
- 状态：已实施并通过验收
- 依据：`requirements-analysis.md`、`discussion-notes.md`、`demo.html`
- 实施结果：方案已落地至正式页面，总体验收索引见 `../design-qa.md`，本专项详细验证见当前目录 `design-qa.md`。

## 2. 已确认方案摘要

CrossETF 继续使用一套 Vue 数据和业务逻辑，在前端根据视口提供两种展示：

- 桌面端：保留现有完整数据表格。
- 手机端：使用紧凑卡片列表，默认只展示四项核心数据。
- 点击手机端单条 ETF：在当前卡片内行内展开该标的其余数据。
- 不新增后端接口，不复制业务计算，不引入构建工具或移动端框架。

手机端默认字段：

1. ETF 代码与简称。
2. 实时溢价率。
3. 涨跌幅。
4. 现价。

手机端展开详情：

- 综合费率。
- 实时估值（IOPV）。
- 公布净值。
- 成交额。
- 市场标识。
- 跟踪指数。
- 当前数据对象中其他已存在、适合展示的辅助字段。

## 3. 断点与适配范围

### 3.1 展示断点

- `< 640px`：手机卡片列表。
- `>= 640px`：现有桌面表格。

使用项目当前 Tailwind `sm` 断点，不新增自定义断点。

### 3.2 验收尺寸

- 320×568：保证不破版，信息仍可辨认和操作。
- 375×667：常见小屏手机。
- 390×844：主要手机验收尺寸。
- 430×932：大屏手机。
- 768×1024：平板和桌面表格切换验证。

### 3.3 横屏

本次不单独设计横屏模式。横屏按照 CSS 可用宽度自然进入对应断点；不保证专门优化的横屏信息布局。

## 4. 页面结构调整

正式改动集中在 `static/index.html`。

### 4.1 顶部品牌与状态区

手机端拆为稳定的三层结构：

1. 品牌行：图标、CrossETF、版本号。
2. 状态行：历史归档天数、标的池在线/缓存状态。
3. 操作行：刷新周期、主题、同步、即时刷新。

要求：

- 所有状态胶囊使用 `whitespace-nowrap`，禁止单字竖排。
- 操作区使用网格或确定的分组，不依赖任意 `flex-wrap`。
- 主要操作触控高度至少 44px。
- 桌面端保持当前紧凑横向布局。

### 4.2 宏观指标

- 手机端保留 2×2 网格。
- 默认显示指标名称、核心数值和涨跌幅/样本数。
- 手机端隐藏更新时间等低优先级信息。
- 辅助文字保持可读，不继续使用 9px 承载重要信息。

### 4.3 分类 Tab 与排序提示

- 手机端两个 Tab 使用两列等宽布局。
- Tab 最小高度 44px。
- 排序状态单独占一行，避免挤压 Tab。
- 溢价分档图例已从正式页面移除；溢价率数值及其颜色显示保留。
- 当前默认排序继续为实时溢价率升序。

### 4.4 核心宽基 ETF 列表

同一份 `sortedList` 同时驱动：

- 手机卡片：`sm:hidden`。
- 桌面表格：`hidden sm:block`。

手机卡片默认层采用四列信息结构：

- 左侧：代码与简称。
- 中间：实时溢价率。
- 右侧：涨跌幅、现价。

卡片整条作为可点击按钮或包含语义明确的展开按钮。展开时在原卡片下方显示详情，不打开新页面。

### 4.5 行业与主题 ETF 列表

- 使用与核心宽基一致的手机卡片结构。
- 默认层仍只展示四项核心数据。
- 跟踪指数放入展开详情。
- 数据源继续使用现有 `sectorList`，不新增分支口径。

### 4.6 换仓测算器

- 保留现有手机单列结构。
- 标题与说明在手机端上下排列。
- select 和 input 高度至少 44px。
- 计算结果在空间不足时允许变为单列。
- 不改变计算公式和风险声明。

### 4.7 风控知识区

- 保留现有折叠结构。
- 增加 `aria-expanded` 和 `aria-controls`。
- 手机端正文不低于 12px，并保持足够行高。

### 4.8 历史档案

本次继续使用现有居中弹窗，不扩大为新页面或底部抽屉，控制改动规模。

移动端调整：

- 弹窗接近全宽，保持安全边距。
- 标题、日期、均溢价摘要允许纵向排列。
- 关闭按钮至少 44×44px。
- 增加 dialog 语义、背景滚动锁定、Escape 关闭和焦点恢复。

## 5. 状态与交互设计

### 5.1 展开状态

新增一个前端响应式状态，例如：

```text
expandedEtfCode: null | string
```

行为：

- 点击收起状态的卡片：展开该卡片。
- 点击已经展开的卡片：收起。
- 点击另一卡片：关闭原卡片并展开新卡片。
- 切换纳指/标普 Tab：清空展开状态。
- 数据刷新后，如果展开标的已不存在：清空展开状态。

只保存一个代码，不复制 ETF 数据对象，避免刷新后出现旧数据。

### 5.2 排序

- 手机端沿用现有 `sortKey`、`sortAsc` 和 `sortedList`。
- 默认仍按实时溢价率升序。
- 本次不为手机端新增复杂排序面板。
- 手机端只显示当前排序说明；桌面端继续允许点击表头排序。

### 5.3 空值与异常数据

- 沿用空值无论升降序均稳定沉底的业务规则。
- 默认卡片中空值显示 `--`。
- 没有有效现价或估值时不错误标记为最低溢价标的。
- 详情字段缺失时显示 `--`，不隐藏整个详情结构。

## 6. 可访问性要求

- 卡片展开控件必须是原生 `button`，或提供等价键盘操作。
- 使用 `aria-expanded` 暴露展开状态。
- 使用 `aria-controls` 关联详情区域。
- Tab 使用 `role="tablist"`、`role="tab"` 和 `aria-selected`。
- 桌面排序表头内部改为按钮，并使用 `aria-sort` 表达排序状态。
- 所有主要操作具备清晰的 `focus-visible` 样式。
- 纯装饰元素不进入读屏顺序。
- 详情内容保持合理 DOM 阅读顺序：代码/名称 → 四项核心数据 → 其余指标。

## 9. 验收标准

### 布局

- 320px 及以上无文档级横向滚动。
- 不出现单字竖排、控件遮挡或卡片内容越界。
- 桌面端完整表格保持可用。

### 信息

- 手机默认层只展示已确认的四项核心数据。
- 点击单条后能看到该标的其余数据。
- 详情数据与桌面表格来自同一对象，数值一致。

### 交互

- 同时最多展开一条。
- Tab 切换后展开状态被正确清理。
- 按钮触控目标不小于 44px。
- 键盘可聚焦并展开/收起卡片。

### 业务回归

- 实时溢价率、涨跌幅、价格和 IOPV 显示口径不变。
- 空值沉底规则不变。
- 最低溢价标识不误判无效数据。
- 换仓测算器计算结果不变。
- 历史归档功能不变。

### 技术

- 不新增第三方依赖。
- 不新增构建流程。
- 浏览器控制台无错误。
- 现有回归测试全部通过。

## 10. 非本次范围

- 原生 App、PWA 或离线缓存。
- 后端接口重构。
- 新的历史趋势图。
- 完整视觉品牌重构。
- 手机端专属底部导航。
- 用户自定义字段或卡片排序。
- 横屏专门布局。

## 11. 回退策略

- 手机卡片与桌面表格使用独立响应式容器；若手机卡片出现严重问题，可先隐藏卡片并恢复原横向表格。
- 不改变后端和数据结构，因此回退只涉及 `static/index.html` 和对应测试。
- 实施时保持单次提交范围聚焦，方便通过 Git 恢复。
