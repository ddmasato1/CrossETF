# A股重点宽基ETF分钟成交额：数据源实测记录

核查日期：2026-11-06，北京时间收盘后，首轮约15:27开始。
当时状态：只做接口调研；未接入产品，未保存原始行情响应，未进行完整交易日稳定性观察。本文保留初次研究时的名单与结论；2026-11-09最终实现为固定10只、四指数及独立日线，已纳入v1.9.0并集中验证，见[发布验收](release-v1.9.0.md)。完整交易日稳定性仍未充分验证。

## 1. 结论与适用范围

东方财富可直接返回一分钟成交额，腾讯分时可返回逐分钟累计成交额。当前数据条件足以继续设计一分钟成交额观察功能。

短时请求成功不代表长期稳定。盘中最新一分钟的出现时间、实际延迟及修订规律均未验证，不能表述为“已经确认全天实时稳定”。

本次在本地网络环境通过Python标准库urllib直接访问接口，未安装或调用AKShare。AKShare是接口封装，不是独立于东方财富的另一份行情源。

## 2. 样本与重复请求

覆盖11只ETF：510300、510310、159919、159925、510050、510500、512100、159845、588000、588080、159915。

东方财富一分钟、东方财富五分钟、腾讯当天分钟三类接口各做三轮，每轮每类11只，共99次，全部返回有效行情记录；单次耗时约0.16～0.55秒。少量探索及后续口径核查请求未计入99次。

## 3. 东方财富一分钟分时

端点：`https://push2his.eastmoney.com/api/qt/stock/trends2/get`。

本次参数：

- `secid=1.510300`，沪市前缀1、深市前缀0。
- `ndays=5`、`iscr=0`。
- `fields1=f1,f2,f3,f4,f5,f6,f7,f8,f9,f10,f11`。
- `fields2=f51,f52,f53,f54,f55,f56,f57,f58`。

`data.trends`返回逗号分隔记录，本次顺序为时间、开盘价、收盘价、最高价、最低价、成交量、成交额、均价。成交额在零起始下标6，单位为元。正式接入前仍需核对字段与时间口径。

11只均返回2026-11-02至2026-11-06共5个交易日，每日241条，共1205条；包含09:30开盘点，最后为15:00。未发现重复时间或负成交额。

| 09:31 | 553756208 |

## 4. 东方财富五分钟K线

端点：`https://push2his.eastmoney.com/api/qt/stock/kline/get`。

本次参数包括`klt=5`、`fqt=0`、`beg=20200101`、`end=20500101`、`lmt=10000`及相应字段选择。

510300当日一分钟合计为5211672665元，五分钟合计为5215567773元，相差3895108元，约0.075%。差异原因未确认，不能擅自归因于舍入、盘后交易或其他机制。

五分钟数据可作为辅助研究，不能拆分成真实的一分钟历史；当前主方案仍采用一分钟。

## 5. 腾讯分时

当天端点：`https://web.ifzq.gtimg.cn/appstock/app/minute/query?code=sh510300`。

最近5日端点：`https://web.ifzq.gtimg.cn/appstock/app/day/query?code=sh510300`。

单条格式示例：`0931 4.111 1608080 660734925.00`。成交量、成交额为累计值，不能直接当作单分钟值；成交额需按交易日内相邻有效记录差分。

本次当天数据延续到15:28～15:29，包含15:00之后记录。510300在15:27～15:28累计成交额为5215567619.93元，15:29变为5211672667元，出现回退。其他样本当天序列也检出了累计金额下降。

因此需核实并过滤目标交易时段，处理上游修订和累计值回退；不能将负差分直接展示，也不能把所有15:00后记录纳入异动判断。金额变动原因尚未确认。

交叉核验中，东方财富一分钟全天合计与腾讯当天响应最后一个累计金额接近：11只差异为0～122元，510300仅差2元。这支持全天金额大体一致，但不能证明逐分钟时间归属完全一致。

项目现有快照源`https://qt.gtimg.cn/q=...`也能批量取得当天累计成交额，可作总额核验。快照本身不提供完整历史分钟，不能据此还原漏采分钟。

## 7. 主源建议及下一步

优先评估东方财富一分钟分时，腾讯作为备用与总额核验来源。公开接口本次可访问，不等于取得正式稳定性承诺。

在交易时段按候选30～60秒周期进行持续观察，至少核查：

1. HTTP与有效数据成功率、空响应、超时、单次耗时。
2. 最新分钟是否持续前进，实际延迟和当前未完成分钟的修订规律。
3. 11只数据的更新步调、漏点补回、同分钟归属。
4. 开盘、午休衔接、收盘集合竞价及15:00后数据的处理。
5. 主备源的逐分钟差异及累计值回退。
6. 最终部署环境的连通性；本地结果不能代表服务器网络。

原始响应未落盘，本记录保存本次观察摘要。最终接入前需重新取得样本核实。

## 2026-11-09正式服务器补充核查与未发布采集方案

以下核查发生于正式服务器oracle-138。访问及诊断为只读，未修改正式代码、容器或档案。前面的东方财富优先建议属于早期研究，当前未发布实现调整为腾讯分时优先、东方财富按需备用；日线继续使用东方财富。

### 已观察到的网络与覆盖情况

- 正式容器健康，页面和API可访问；近期650行日志中检出87次上游错误：60次TLS握手超时、12次读取超时、15次网络不可达，没有403／429记录。失败标的会变化，符合间歇性连通故障，不能认定为固定代码不支持或已触发风控。
- DNS同时返回IPv4与IPv6，IPv6存在无路由现象；IPv4连接和TLS可成功，随后普通urllib及IPv4限定请求也曾连续成功。当前证据不足以把IPv6认定为唯一故障原因，也不把短时成功解释为长期稳定。
- 腾讯当日分时在该服务器覆盖最终10只ETF与四指数。过滤交易时段后各有241个标准分钟；原始ETF响应可有247条、指数242条，必须丢弃15:00后记录。此轮单次约0.18～0.24秒。
- 腾讯510300近5日接口可取得逐日记录及`prec`。510300当天241个分钟与已保存东方财富数据比较，235分钟差异不超过1元，最大差异58.01元；09:30分别为32454287.82元与32454234元，11:30及13:01金额相同。其他9只尚未全面逐分钟金额交叉核验。
- 腾讯minute/query用逗号拼接代码返回`code=-1`、`code param error`，不支持此次尝试的批量方式；14个标的完整分时仍需14次。`qt.gtimg.cn/q=`支持一次批量取得这14个标的的行情快照。
- 新浪1分钟接口可取得抽样两只ETF的`amount`，各238条当日记录，首条09:31且尾盘缺14:58／14:59等分钟；上证指数239条。与当前09:30开始、241分钟的口径不同，本轮不直接拼入。一次TLS失败后重试成功，也不能据此断言接口不可用。
- 腾讯／新浪抽样日K没有核实到满足三年需求的每日成交额，不能用价格乘成交量近似替代；日线维持东方财富。

### 请求预算与数据口径

当前代码采用以下策略，尚未发布新版本或部署正式环境：

| 任务 | 调度与请求数 |
| --- | --- |
| 10只ETF与四指数行情快照 | 一次批量请求；上次请求完成后至少间隔60秒 |
| 完整分时校准 | 每次一个标的，上次完成后至少间隔20秒；正常14个约5分钟一轮 |
| 启动近5日补采 | 同样逐标的分散执行，不再启动三轮集中重试 |
| 东方财富备用 | 腾讯单标的失败后才尝试一次，与主源共用预算 |
| 日线及首次三年补采 | 与分钟共用预算，可使分钟校准进一步延迟 |

硬上限为同一进程内A股观察模块任意滚动60秒最多5次上游请求，任意两个请求开始之间至少12.5秒。预算使用线程锁与单调时钟，禁止HTTP自动重定向；所有上述实际请求都通过同一transport。冷却中的来源直接跳过网络，HTTP 403／429至少冷却300秒并遵守有效Retry-After，连续3次网络失败后开始递增冷却。错过的定时任务不集中补发，页面刷新不发上游请求。原首页腾讯行情和其他原有后台任务不在此预算内；进程重启会重置内存计数和冷却。

每5分钟约19次是无故障、无日线竞争时的规划量（5次快照＋14次分时），实际还受请求耗时、间隔与预算约束，不能当作严格刷新时限。公开行情接口没有核实到官方频率或稳定性承诺；代码限制自身请求数，不能承诺上游绝不风控。

腾讯分时累计成交额按同一响应、同一交易日相邻标准分钟差分。09:30为首条累计金额；午休后的13:01接11:30；前一分钟缺失时不把跨分钟差额塞进当前分钟。累计回退拒收本次响应，缺失保持空值；每个实际保存的分钟记录来源。历史指数使用当天的`prec`，仅在日期匹配时才允许引用qt前收。

批量快照金额以万元转元，仅保留预览信息，不进入正式分钟成交额。指数图例可以显示快照点位／涨跌幅及其原始时间，曲线仍使用完整分时序列；主图累计、排行保持同一齐备完整分钟集合。历史查询不套用当前日快照。请求预算及来源冷却可通过分钟API的`collector`字段核查。
