# A股重点宽基ETF一分钟成交额观察：需求与设计草案

日期：2026-11-06。
当前状态（2026-11-09）：固定10只核心ETF、分钟合计与四指数、成交额排行、三年日成交额与上证指数已实现，纳入v1.9.0；用户已授权最终集中测试、更新文档、提交与推送。87项自动化回归及桌面浏览器交互通过，见[发布验收](release-v1.9.0.md)。当前实现以第16—18节为准；下文保留方案演变及当时的未测试／未提交状态，不作为当前发布状态。新页移动适配、盘中延迟与全天稳定性仍待后续验证。

## 1. 核心使用场景

用户在交易日打开页面，快速查看：

1. 哪些重要指数组对应的ETF正在出现巨额成交？
2. 多个指数组是否在同一分钟或相近时间一起放量？
3. 这些分钟相比平常究竟放大了多少？
4. 收盘后，当天有哪些明显的集中成交时段？

第一版的价值是呈现可观察的成交异常，保持信息简单、直接。

## 2. 监控对象

指数本身不是本功能直接统计成交的对象；统计对象为跟踪相应指数的场内ETF。

按指数归组，每组选择固定的主要ETF，汇总组内一分钟成交额。图上明确写“所选ETF合计”，不把样本成交额称为该指数全部成交额。单只ETF可以展开查看。

|---|---|

组内产品数量不同，跨组比较需同时看各自历史放大倍数，不能只按绝对金额衡量异常程度。成分股可能重叠，六组同时放量表示多个ETF渠道同步活跃，不代表六组相互独立的资金证据。

如果后续调整监控名单，应使用同一名单重算比较期，或明确标记基准变化，避免因新增ETF产生虚假放量。

## 3. 一分钟成交额口径

- 单只ETF：某一分钟内实际成交的金额，源数据单位为元。
- 指数组：该组所选ETF在同一交易日、同一分钟的成交额之和。
- 页面按金额大小使用亿元或万元展示；内部保留元口径。
- 当日累计：截至当前完整分钟的有效分钟成交额之和。
- 当前尚未结束的分钟可单独展示为“进行中”，数值允许更新；不与完整历史分钟直接比较，不参与正式异动判定。
- 时间按北京时间解释，交易日期使用上游数据日期，不能把请求日期直接当成数据日期。

上游09:30的开盘集合竞价点、午间衔接和15:00收盘集合竞价点需核实归属并单独明确口径。保留上游时间标签，不未经核对就将时间整体平移一分钟。

## 4. 主视图建议

本节保留早期方案；2026-11-06用户反馈后，当前实现已调整为ETF分钟成交额蓝柱与真实指数点位橙线叠加的大图，详见第14节。历史基准不再叠加在主图中。

早期建议：采用六个上下排列、时间轴对齐的小图，每个指数组一行，主图统一为一分钟成交额柱状图。

- 横轴为当天交易时间，午休不作为零成交连续填充。
- 纵轴为分钟成交额，各组可采用独立尺度，必须清楚标明；跨组柱高不代表相同金额。
- 鼠标移动到同一时间时，六组联动显示该分钟的金额、历史基准与放大倍数。
- 可叠加历史相同分钟的基准曲线，让异常尖峰容易辨认。
- 每组旁边展示最近完整一分钟成交额、相对历史倍数、当日累计成交额。
- 展开组内ETF，查看尖峰来自哪几只产品。
- 手机端按组纵向排列，点击或触摸查看分钟详情，不能依赖鼠标悬停才能读取数据。

视觉重点是让多个指数组在同一时间出现的高柱形成明显对齐的尖峰。本文仅记录布局意图，不生成图表或页面原型。

## 5. 历史基准建议

建议比较过去若干交易日的相同分钟，基准采用中位数，以减少历史极端成交的影响。

放大倍数 = 当前完整分钟成交额 / 历史相同分钟成交额中位数。

目标比较窗口可考虑过去20个交易日，但目前一分钟接口本次只取得最近5日，包含当天，不能立即声称已有20日一分钟基准。可采用以下分阶段方式，具体窗口待确认：

- 初期：使用实际取得的历史分钟数据，显示“基于前N个有效交易日”；包含当天的5日返回最多提供4个此前交易日样本。
- 后续：持续保存一分钟数据，积累到目标窗口后再使用完整20日基准。
- 历史不足时仍显示原始成交额；样本过少时不输出确定性自动异常等级。
- 基准为零、缺失或样本不足时，放大倍数显示不可用，不能产生无穷倍或把故障当成天量。

五分钟历史不能拆分成五条真实的一分钟历史，不用其替代20日一分钟基准。

## 6. 同步放量与异动记录建议

人工观察尖峰是首要能力；自动标记作为辅助，需同时考虑：

- 相对各组自身历史基准的放大倍数。
- 一分钟成交额的绝对规模。
- 相近时间触发的指数组数量。

倍数门槛、金额门槛、至少几组触发，以及“相近时间”的容忍范围均待历史样本校准。目前不将3倍、三组等讨论示例写为最终规则。

如加入异动记录，建议展示时间、涉及指数组、成交金额和倍数，连续的一波事件合并呈现。文案使用“多指数ETF同步放量”等事实描述，不直接标注国家队买入。

开盘与收盘集合竞价需与各自历史同口径比较，避免与普通连续竞价分钟混用。

## 7. 数据获取与异常状态

候选方案为东方财富一分钟分时作为主源，腾讯分钟分时作为备用与核验来源。详情见[数据源实测记录](data-source-assessment.md)。

- 服务端统一拉取并缓存，多个页面访问复用结果，避免按每个用户分别请求上游。
- 候选刷新周期为30～60秒，最终频率取决于盘中实测；“一分钟粒度”不代表已证明秒级延迟。
- 每次拉取可补齐当天序列；按ETF、日期、分钟更新已有记录，处理上游对未完成分钟的修订。
- 单只缺失时不能按零成交计算。组内不齐时标注不完整，暂停该组正式放量判断。
- 同步判断只比较数据已经齐备的共同完整分钟，避免把更新较快和较慢的产品错配。
- 上游失败时展示最后有效数据及数据截止时间，明确提示更新异常；旧数据不能冒充当前分钟。
- 如果启用备用源，先核实逐分钟口径；累计值按交易日做差分，排除非目标交易时段，并处理回退、修订、缺点等情况。不能仅凭全天合计接近就直接逐分钟混拼。
- 保存原始来源与数据时间，防止源切换或累计金额修订制造虚假尖峰。
- 休市日展示最近交易日并标明日期，不生成当天零成交序列。

未来如实施，应遵守项目现有纯Python标准库、轻量JSON持久化的约定；独立保存本功能数据，不写入既有跨境ETF收盘档案。后台采集与页面访问解耦，具体接入方式待实施设计。

## 8. 数据保存方案

建议保存单只ETF的一分钟成交额，供历史同时段比较和收盘回看。以下保留周期与目录为建议值，尚未实施。

### 保存内容与目录

- 放在独立目录`data/a_share_etf_volume/`，按交易日期分JSON文件，例如`2026-11-06.json`。
- 文件记录格式版本、交易日期、标的名单及分组版本、最近成功拉取时间；每只ETF记录代码、分钟时间、成交额（元）、来源和质量状态。
- 区分已完整分钟与进行中分钟；保留数据截止时间，不能用最近请求时间代替行情时间。
- 保留单只ETF数据作为重新分组、计算及核验的依据；组内合计、历史基准和倍数可重新计算，不必重复存成长期档案。
- 运行时行情文件不提交Git；未来实施时需核实或补充忽略规则。

### 更新、补采与安全写入

- 后台采集与页面访问解耦；无人打开页面时仍按交易时段采集，未来需确定服务启动与运行方式。
- 每轮成功拉取后，按ETF、日期、分钟合并；同一分钟覆盖更新，不追加重复记录。
- 只写入已校验的有效数据；失败或缺失不覆盖已有有效数据，不填零。
- 进行中分钟允许持续修订；完整分钟如被上游修订，也需更新并使相关计算缓存失效。
- 首次启动或恢复运行时，利用接口实际可取得的最近5日数据补采；超过窗口的缺口如实保留，不用五分钟数据或均分金额伪造。
- 收盘后再次拉取并核验当日完整性，具体时间在盘中实测后确定；不将拉取成功等同于全天数据齐全。
- 每轮合并后集中写入发生变化的日文件，采用临时文件加`os.replace`原子替换，写入串行化，避免半文件及并发覆盖。

### 保留周期与规模

建议先保留最近60个交易日，满足20日比较并留出回看余量。休市日不生成空文件，缺失交易日不因没有文件而被当成休市。

按本次11只ETF、每只每天241条估计，每天2651条，60个交易日约159060条。具体磁盘体积取决于JSON结构，不预先承诺大小；该规模可沿用项目轻量JSON方案，无需数据库。

清理仅针对本功能目录中已识别的过期日期文件，不能影响其他模块。保留不足或采集中断时，在页面显示实际历史样本数。

## 9. 计算方案

一分钟成交额由主源直接提供，核心计算为加总、中位数和比值，不根据价格乘成交量估算。

| 计算项 | 计算方法 | 主要约束 |
|---|---|---|
| 指数组分钟成交额 | 该组所有所选ETF同一分钟成交额之和 | 成员齐备且分钟完整才作为正式有效值 |
| 当日累计成交额 | 从当日开盘点至当前完整分钟的成交额之和 | 有缺口时标明累计不完整，不能冒充全天完整合计 |
| 历史同时段基准 | 先计算各历史日同组同一分钟合计，再取这些日合计的中位数 | 不将各只ETF的中位数相加替代组内历史中位数 |
| 放大倍数 | 当前完整分钟组内成交额除以历史同时段基准 | 基准须为正且样本达到要求；否则不可用 |
| 同步放量组数 | 在共同完整分钟，统计同时达到倍数及绝对金额门槛的组数 | 门槛与时间容忍范围待校准；缺失组显示不可用 |

### 历史窗口与边界

- 建议从当前交易日之前的最近20个交易日中取样，排除当天，避免当天成交进入自身基准。
- 每个历史分钟只纳入同一名单下、成员齐备且来源口径可比的有效记录；窗口内缺失样本不填零，并展示实际N值。
- 初期不足20日时显示实际样本数；输出倍数和自动等级所需的最小样本数待确认。
- 基准为零、负值、缺失时不计算倍数；零成交只有在上游明确返回有效零值时才保留。
- 开盘集合竞价与收盘集合竞价使用对应历史时间标签比较；午休不生成成交分钟。
- 当前分钟未结束、源数据落后或组内不齐时，不触发正式同步放量事件。
- 如自动阈值尚未确定，首版可只展示原始柱、历史基准和有效倍数，由用户观察，不提前输出自动等级。

计算示例：某组完整分钟成交8亿元，历史同分钟组内合计的中位数为1亿元，则放大倍数为8倍。该例只说明计算方法，不代表自动报警门槛。

### 计算与缓存时机

历史基准建议在交易日开始前或首次加载时计算并缓存；历史补采、源数据修订、分组变化时重算受影响部分。每轮更新只需更新当天分钟合计、累计值及相关比值，多个前端访问复用同一结果。

备用源使用累计成交额时，先按日内相邻有效记录差分转换。中间缺失分钟的差额覆盖多个分钟，不能全部计入最后一分钟；首条累计值、累计回退和修订均需按核实后的源规则处理。无可靠转换结果时不参与正式计算。

数据规模较小，计算本身预计负担有限；真正需要验证的是数据一致性、采集连续性与时间归属，而非复杂计算性能。

- 六组时间轴对齐，支持悬停、手机触摸锁定、分钟下拉选择、ETF成分展开、明暗主题和可展开的精确金额表格。
- 没有自动报警、同步放量阈值或资金身份推断。倍数是描述性比较，有至少1个有效历史样本且中位数为正时可显示，并同时标明实际N；最小可信样本和自动等级仍待后续校准。
- 第一版仅接入东方财富，腾讯备用源尚未接入。计算结果使用独立3秒内存缓存，历史基准暂随载荷重算，未单独建立长周期基准缓存。
