2. 按任务查阅本文链接的功能专题，再定位`app/`业务模块、`static/`页面及`tests/`对应测试；专题中的旧方案和历史验收记录须结合本文当前口径阅读。
3. 修改与验证遵循[测试说明](../tests/README.md)：开发期间不逐次运行测试，最终提交前使用`./scripts/run_tests.sh`集中执行。部署方式见[README](../README.md#部署)。

## 项目与架构

- 跨境ETF溢价监控、同指数价差示意、独立纳指定投参考及收盘档案。
- 后端为Python 3.11标准库，首页为Vue 3及Tailwind CDN；独立观察页为Vue 3及本页CSS，无pip/npm依赖或数据库。
- `server.py`：启动配置、后台线程启动、HTTP路由、静态资源与响应组织；业务不依赖HTTP请求对象。
- `app/core/config.py`：版本号、项目根目录、数据目录及监听配置；后端版本入口为`APP_VERSION`，仍需与首页版本同步。
- `app/core/storage.py`：业务JSON文件的按路径重入锁、原子写入、临时文件清理及可选fsync；业务格式校验和降级保留在各模块。
- `app/market/quotes.py`：跨境ETF标的发现、行情采集／解析／计算、缓存与后台收盘调度，管理刷新共用行情锁。
- `app/market/history.py`：跨境ETF收盘种子初始化、幂等归档、历史查询与原始字节读取；不导入HTTP或行情模块。
- `app/signals/nasdaq.py`：独立情绪、估值及每日定投状态机与后台评估，保留各自低频缓存和锁。
- `app/a_share/volume.py`：10只核心ETF和四指数分钟采集、完整性边界、历史基准、排行与日档保留。
- `app/a_share/daily.py`：固定起点的日成交额及上证指数收盘，收盘更新、补采、错误恢复与独立长期日档。
- `app/a_share/sources.py`：腾讯分时与批量快照解析，累计差分和逐日前收隔离。
- `app/a_share/requests.py`：A股观察的分钟／日线共享预算、来源冷却及禁止自动重定向。
- `static/index.html`：手机卡片、桌面表格、宏观详情、投入倍数浮层和历史弹窗；`static/a-share-volume.html`：独立成交观察页，两套滑轨与共用主题。
- `data/`：目录挂载持久化；正式档案和运行缓存均不提交Git。文件打开、JSON编解码和替换收敛于公共存储层；分钟按日合并与跨境收盘归档均持有完整读／改／写事务锁，锁内不请求上游。
- `tests/`：按`acceptance/`、`market/`、`signals/`、`a_share/`、`http/`、`core/`分类；使用模拟上游和临时档案，入口说明见[测试目录](../tests/README.md)。
- `scripts/start.sh`：切换至项目根目录后启动服务；`scripts/run_tests.sh`：提交前集中执行综合验收、行情并发及全部unittest回归。
- `docs/`：交接与各功能专题文档；根目录保留README、CHANGELOG、部署配置及服务入口。

## 金融业务边界

1. ETF估值优先使用腾讯IOPV（fields[78]）；溢价优先使用fields[77]，缺失时按现价/IOPV计算。IOPV缺失时回退公布净值fields[81]并标记nav_fallback。
2. 公布净值日期未严格核验；期货、汇率及其联动乘数不用于重建ETF动态净值。
3. 无现价或无可用估值基准时，溢价为空，升降序均沉底；合法0.0%保留。
4. 价差示意只比较同指数标的，不代表实际套利利润或净值敞口增量，未扣费用与滑点。
5. fields[40]为S时标记临时停牌，不阻断IOPV追踪，收盘归档不写该状态。
6. 费率由ETF_TOTAL_FEES维护；标的池通过天天基金发现，失败时使用本地缓存或DEFAULT_*内置列表。
7. 美债、情绪、估值及定投建议不干预ETF估值、排序、价差测算或收盘归档。

## 定投参考（2026-11-03当前授权规则）

完整定义见[因子方案](nasdaq-dca-indicator/factor-redesign-proposal.md)。本节为v1.8.0实现口径，替代旧60/25/15评分规则；发布前33项功能回归通过，阈值未做策略回测。旧评分历史验证仅反映此前版本。

- PE指上游PE分位，情绪为恐惧贪婪指数；默认正常1B。`(PE≤30 且 情绪≤25) 或 (PE≤15 且 情绪≤45)`候选加投1.5B，受用户预留预算上限约束；`PE≥85 且 情绪≥75`候选停投0B，其余正常。
- 加投后以`PE>40 或 情绪>45`候选退出正常；停投后以`PE<80 或 情绪<65`候选退出正常。所有转换含首次确认均须同一候选连续3次合格评估，候选变化重新计数，断档／缺测／无效中断计数，确认期间保留原已确认行动。
- 停投确认后，仅对已有持仓且超过预设配置目标提示“考虑止盈”，不自动卖出。
- 独立标准库后端`/api/nasdaq-dca`，后台循环和API共用北京时间周一至周五16:00起每天最多一次评估；此前不新增评估、漏过日不补算，周末不算断档。当前没有节假日日历，须披露。状态持久化至`data/nasdaq_dca_state.json`并须排除Git，不改变ETF计算或归档。
- 允许真实有效缓存，不虚构历史；估值超过7天或情绪`as_of`超过72小时不得确认新建议。失败保留原行动及最后成功评估时间，无已确认行动则“数据不足，按自己的计划执行”，不发信号；首次有效数据暂按正常1B并标“信号观察中”，满3次才确认。
- 仪表为加投／正常／停投三个等宽区，指针为离散行动，中心`1.5×／1×／0×`，无风险评分或加权百分数。PE／情绪为输入，10Y仅作背景；保留紧凑布局，常显解释、评估日期、源时间及“加码信号观察中：已满足1天，连续满足3天后生效”等完整进度句；悬浮仅说明倍数与确认机制，完整规则放入默认折叠的“规则说明”。
- 不恢复52周位置及额外usQQQ请求；阈值未回测。核心套件已改为验证每日建议展示，另有10项独立定投状态机回归，全部通过；旧版评分验收仍仅是历史记录。

## 接口与缓存

| 路径 | 用途与边界 |
| --- | --- |
| /api/quotes | ETF及宏观行情；3秒内存缓存，并发合并，有效期从刷新完成起算 |
| /api/fear-greed | 独立情绪；成功缓存60分钟，失败后10分钟内不重复请求，旧数据可降级 |
| /api/nasdaq-valuation | 独立NDX估值；成功/失败均冷却6小时，最近尝试时间持久化，固定上游、无强制刷新参数 |
| /api/nasdaq-dca | 每日定投行动及确认进度；独立持久化、16:00起按工作日每日评估，读取不重复累计 |
| /api/history | 收盘档案，支持days参数 |
| /api/refresh-symbols | 管理重扫；公网入口必须阻断，重扫与行情刷新共用锁 |
| /volume | 独立A股成交观察页，当前桌面优先 |
| /api/a-share-volume | 分钟成交合计、四指数点位及前收涨跌幅、排行，支持date参数 |
| /api/a-share-volume/dates | 已保存分钟档案交易日期 |
| /api/a-share-volume/daily | 每日成交额合计与上证指数收盘，支持start/end闭区间，只读本地档案 |
| /health | 容器健康检查 |

- `data/history_daily.json`为生产档案；缺失时从受跟踪的`.example`模板初始化。
- `nasdaq_symbols_cache.json`、`fear_greed_cache.json`、`nasdaq_valuation_cache.json`、`nasdaq_dca_state.json`及临时文件均为运行数据，不得提交、暂存或回退。
- 情绪与估值首次无可用数据返回503，旧数据降级返回200及状态字段。
- 估值前端在启动、手动刷新及6小时定时器读取，秒级行情轮询不调用该接口。
- 数据时间与成功拉取时间不得被页面刷新时间替代。情绪缓存标签按用户要求隐藏，后台状态仍保留。
- 后台收盘线程工作日15:02～15:30每分钟巡检，强刷行情并按日期幂等落盘；上游故障或服务停机仍可能导致漏采。

## A股成交观察维护（含2026-11-09未发布采集改造）

- 固定核心池10只、四指数，名单版本v2.0；不采用早期六组或13只扩展方案。当前设计以[需求文档第16节之后](a-share-etf-volume/requirements-design.md)及[日线方案](a-share-etf-volume/daily-history.md)为准，旧分图和已移除明细仅为演变记录。
- 分钟腾讯优先，东方财富trends2按需备用；腾讯累计金额（元）仅按同日相邻标准分钟差分，缺点不跨段差分、回退拒收、过滤15:00后记录。来源按分钟保存，旧档案继续可读；历史指数使用逐日前收，缺少可靠前收时仅显示点位。
- 后台启动将14个标的的近5日补采分散执行，盘中单次分时结束后至少间隔20秒再处理下一标的；每次最多处理一个标的，不补发积压轮次。10只ETF与四指数的批量快照单次完成后至少间隔60秒，正常完整分时约5分钟覆盖一轮，失败或日线竞争预算时更慢。
- 同一进程内A股分钟、快照、启动补采、备用请求和日线共享预算：任意滚动60秒最多5次，相邻请求至少12.5秒。403／429至少冷却5分钟并遵守有效Retry-After；连续3次网络失败起递增冷却。禁止HTTP自动重定向，冷却来源不发请求。首页原有行情与其他后台任务另计，不应把5次上限理解为整个应用的总请求数。
- 采集时段仍按工作日09:25～11:35、12:55～15:35判断，尚未接入节假日日历；非时段内完成一次分散启动补采后等待下一采集时段。仅在失败标的后续轮转时重试；不再启动三轮密集重试。
- 快照只在当天最新指数图例提供读数，明确标明快照时间和曲线截止。分钟柱、累计及排行不使用快照累计差额，仍以10只齐备完整分钟为准；未结束分钟不得累计，也不能仅因时间过去将已保存半分钟视为完整。缺任一ETF，合计留空。
- `/api/a-share-volume`的`collector`返回上限、实际近60秒请求数、启动后请求数、冷却剩余秒数及快照错误；指数的`index_info.snapshot`保留独立行情时间，历史日不套用当天快照。接口和网页刷新均只读本地，不触发上游。
- `data/a_share_etf_volume/YYYY-MM-DD.json`保留最近60个已保存交易日；旧名单记录保留，当前合计仅计10只。`data/a_share_etf_daily/history.json`长期保存原固定起点，勿交给分钟清理逻辑。
- 日线仍使用东方财富，16:00前不接纳当天日K；交易日期参考实际指数／ETF记录，无完整交易所日历。指数和成交额分别标缺，首个交易日前不冒充缺测；159952在2023-11-28全天停牌零成交有官方证据。首次回填会占用共享预算，允许数分钟以上延迟。
- 日线更新失败每5分钟重试；网页暂停自动刷新不停止后台采集；进程停止则停止采集，重启补日线，分钟仅能补源站近5日。
- 已发布版本仍为v1.9.1；当前采集改造与业务／存储结构整理已完成提交前集中回归及隔离容器验证，尚未发布新版本或部署正式环境，验证范围见下节“发布与验证”。`Dockerfile`复制根目录`server.py`及整个`app/`包，默认静态资源和运行数据仍位于根目录的`static/`和`data/`；`app/`模块改动后需重建镜像。运行数据、AGENT.md、scratch不提交。
- v1.9.0历史验收见[发布验收](a-share-etf-volume/release-v1.9.0.md)，当前接口实测和限频方案见[数据源记录](a-share-etf-volume/data-source-assessment.md#2026-11-09正式服务器补充核查与未发布采集方案)。新页移动适配仍不在本轮范围。

## 界面维护约定

- ETF手机卡片<640px，桌面表格≥640px；共享数据与计算，Tab切换清理展开状态。
- 顶部操作栏以768px分界：窄屏两行、宽屏一行；主题与日常刷新保留，低频同步入口在底部折叠维护区。
- 宏观默认折叠，localStorage键nas_macro_expanded；按钮为“展开详情 / 关闭详情”，文字不换行。
- ≥1024px两详情卡各半，否则上下排列；情绪内部<480px上下排列。卡片最小170px、仪表最大160px、图表容器最小110px，内容增加时自然增高。
- 风向标左仪表右三行参考值；底部展示评估进度、时间及快照。悬浮仅简述倍数与确认机制，完整阈值在默认折叠的“规则说明”中。
- 摘要标题统一12px/500字重/灰色，不重复利差；定投行动以蓝色加大、中性灰正常、橙色停止展示，文字优先；止盈为独立附加提醒。
- Canvas在展开后的nextTick重绘，ResizeObserver处理尺寸变化；历史弹窗保留Esc、滚动锁定与焦点恢复。
- 禁止v-html/innerHTML，外部内容仅文本绑定。

## 部署与安全

- 直接运行默认BIND_ADDRESS=127.0.0.1；容器内部0.0.0.0接收转发，宿主机仅发布127.0.0.1:8000:8000。
- 反代/Cloudflare Tunnel从宿主机回环转发；其他容器中的代理使用私有Docker网络，不能把代理自身127.0.0.1当作应用。
- data必须挂载整个目录，避免单文件挂载导致os.replace失败。源代码热挂载与数据卷用途不同，Python代码改动后需重启服务。
- 公网阻断/api/refresh-symbols；用户此前报告Cloudflare已配置/api/按IP限流（15次/10秒，封锁10秒）。这些是外部配置，不由仓库部署或自动验证。
- GitHub Release不等于云端已部署；v1.7.0发布时仅更新本地服务，未操作云端。云端需自行拉取并重建。
- `.gitignore`与`.dockerignore`分别排除运行状态；Docker构建不带历史档案、缓存、定投状态及私有`AGENT.md`，保留`history_daily.json.example`种子。运行数据仍通过整个`data/`目录挂载。
