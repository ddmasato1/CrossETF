# CrossETF - A股跨境ETF实时溢价追踪与收盘沉淀终端

极简、坚固的跨境 ETF 实时折溢价量化监控看板。立足境内 A 股交易市场，盘中实时跟踪**纳斯达克 100**、**标普 500** 及科技细分跨境 ETF 的官方 IOPV 溢价率，全自动沉淀每日收盘情绪档案，内置同类标的价差测算。零第三方依赖，专为云主机与服务器 7×24 小时常驻运行打造。

---

## 🌟 核心功能特性

1. **标的池全自动在线发现与滑动缓存机制**：
   - **在线首选拉取**：每日自动从天天基金全网公募基金代码库动态扫描所有以 `159`（深市）和 `513`（沪市）开头的纳指与标普 ETF，**彻底告别代码写死**，未来新发标的自动感知。
   - **每日持久化缓存 (`data/nasdaq_symbols_cache.json`)**：在线拉取成功后自动持久化至本地数据目录。
   - **前日缓存无缝兜底**：若遇网络中断或上游接口抖动，**自动无缝降级使用前一日缓存的标的库**，保障盘中行情服务永不中断，并在界面清晰展示缓存日期。
   - **标的池全覆盖**：
     - **纳指 100 综合宽基核心池**（12只）：`513390`（博时）、`513110`（华泰柏瑞）、`159513`（大成）、`159632`（华安）、`159659`（招商）、`159660`（汇添富）、`513870`（富国）、`513300`（华夏）、`159696`（易方达）、`159941`（广发）、`159501`（嘉实）、`513100`（国泰）。
     - **标普 500 综合宽基核心池**（4只）：`159655`（华夏）、`513650`（南方）、`159612`（国泰）、`513500`（博时）。
     - **细分行业与主题标的**：全面接入交易所官方发布数据，覆盖 `159509`（纳指科技）、`513290`（纳指生物科技）等。
2. **官方 IOPV 优先的指标口径**：
   - **实时溢价率**：现价与 IOPV 有效时，优先采用腾讯行情返回的 IOPV 溢价率；该字段缺失时，按 `(现价 - IOPV) / IOPV × 100%` 计算。
   - **实时估值 (`est_realtime`)**：优先使用 IOPV；IOPV 缺失时回退到有效公布净值，并按该净值计算溢价率，状态为 `nav_fallback`。
   - **公布净值 (`nav_t1`)**：读取腾讯行情中的公布单位净值，代码尚未核验其发布日期，字段名不保证数据一定来自上一交易日。
   - **宏观参考指标**：CME 纳指期货、标普期货与 USD/CNH 汇率用于宏观展示；其联动乘数不参与当前 ETF 估值或溢价计算。
   - **空值沉底机制**：无有效现价，或 IOPV 与公布净值均缺失时，溢价率为空并在排序中沉底；有效 0.0% 溢价正常保留。
3. **默认按实时溢价率升序自动排序**：
   - 越靠前估值相对越便宜，自动识别全市场有效最低溢价率标的（全场无效时不展示最低标的）。
4. **同指数标的价差金额示意测算器**：
   - 仅限同跟踪指数标的（如纳指 100 内部）比较，由代码强制限制跨指数计算；
   - 测算指标：**溢价率差 (%)** 与 **价差金额示意（卖出金额 × 溢价率差）**；
   - 必须注明：**该金额不代表可兑现利润，也不等于换仓后的净值敞口增量**。
5. **手机端与桌面端双视图**：
   - **手机端（`<640px`）**：ETF 以紧凑卡片展示，默认只保留代码/简称、实时溢价率、涨跌幅和现价四项核心数据；点击单条可在原位展开费率、IOPV、净值、成交额、市场和跟踪指数；
   - **桌面端（`>=640px`）**：继续使用完整数据表格，保留表头排序与高密度浏览能力；
   - 两种视图共享同一份 Vue 数据和计算逻辑，不复制业务口径。切换指数 Tab 时自动清理展开状态，同时最多展开一个标的。
6. **KISS 原则极简设计**：
   - **零第三方依赖**：纯 Python 标准库编写服务端（`ThreadingHTTPServer`），无须 `pip install` 任何额外库；
   - **单页面响应式架构**：基于 Vue 3 CDN + Tailwind CSS CDN，支持自适应轮询、手动即时刷新与在线重扫标的。
7. **独立市场情绪温度**：
   - 展示 CNN 口径恐惧贪婪指数的当前分数、中文等级、五段色温和最近 30 个自然日趋势；低分代表恐惧，高分代表贪婪；
   - 情绪模块使用独立 `/api/fear-greed`、独立 60 分钟缓存和最后有效数据降级，不参与 ETF 估值、溢价、排序或历史归档；
   - 外部情绪源失败时每 10 分钟允许重试，页面继续显示最后有效数据并标注“缓存数据”；首次无有效数据时明确显示不可用。

## 🧮 核心计算公式与数据局限

以下 IOPV 公式适用于 IOPV 有效的情况；溢价率优先取接口字段，仅在该字段缺失时按公式计算。IOPV 缺失而公布净值有效时，以下公式中的 IOPV 替换为公布净值。

$$
\text{实时估值} = \text{交易所官方发布 IOPV}
$$

$$
\text{实时溢价率} = \frac{\text{二级市场现价} - \text{官方 IOPV}}{\text{官方 IOPV}} \times 100\%
$$

后端仍计算以下宏观乘数，但不将其应用到 ETF 估值或溢价。这里的涨跌幅使用小数形式（例如 1% = 0.01）：

$$
\text{宏观环境联动乘数} = (1 + \Delta \text{CME 期货}) \times (1 + \Delta \text{离岸汇率 USD/CNH})
$$

$$
\text{溢价率差（百分点）} = \text{标的A溢价率} - \text{标的B溢价率}
$$

$$
\text{价差金额示意} = \text{卖出金额} \times \frac{\text{溢价率差（百分点）}}{100}
$$

> **数据与测算局限**：
> 1. **基准日期待核验**：公布净值的发布日期尚未核验，净值回退口径与 IOPV 口径应区分理解。
> 2. **无自建动态净值模型**：当前实现不利用期货、汇率或基金持仓重建 ETF 净值。
> 3. **时间对齐与时滞**：尚未实现行情时刻严格对齐与过期行情识别，因此不保证与券商终端在每一时刻显示完全一致。
> 4. **价差示意局限**：卖出金额为输入份额乘以现价，结果按元四舍五入；未扣除交易费用与滑点，不代表可兑现利润，也不等于换仓后的净值敞口增量。

## 🚀 极速启动与使用

在终端中进入项目目录，执行以下任一命令即可：

### 方式一：Docker Compose 一键启动（推荐，适合 NAS / 服务器 / 本地）
```bash
docker compose up -d
```
停止服务：
```bash
docker compose down
```

### 方式二：Docker 原生运行
```bash
# 构建轻量镜像（仅约 50MB，无第三方 pip 依赖）
docker build -t cross-etf:latest .

# 启动容器并挂载独立数据目录（支持安全原子替换）
docker run -d \
  --name cross-etf \
  -p 8000:8000 \
  -v $(pwd)/data:/app/data \
  --restart unless-stopped \
  cross-etf:latest
```

### 方式三：运行本地脚本启动
```bash
./start.sh
```

### 方式四：直接使用 Python 启动
```bash
python3 server.py
```

启动成功后，浏览器打开：
👉 **http://127.0.0.1:8000**

API 接口说明：
* 实时行情数据：`GET http://127.0.0.1:8000/api/quotes`
* 恐惧贪婪指数：`GET http://127.0.0.1:8000/api/fear-greed`
* 每日收盘历史归档：`GET http://127.0.0.1:8000/api/history`（支持 `?days=30` 参数）
* 强制在线重扫标的：`GET http://127.0.0.1:8000/api/refresh-symbols`
* 容器健康检查：`GET http://127.0.0.1:8000/health`

## 💡 溢价指标阅读说明

- **页面“实时溢价率”的含义**：IOPV 有效时采用接口中的 IOPV 溢价率，缺失该字段才按现价与 IOPV 计算；IOPV 缺失时可回退到公布净值。当前实现不使用期货与汇率推算动态净值。
- **为什么现价下跌，溢价仍可能上升？** 溢价取决于现价与估值基准的相对变化。例如现价从 1.10 降至 1.089（下跌 1%），基准从 1.00 降至 0.98（下跌 2%），按公式计算的溢价由 10% 上升至约 11.12%。这是数学示例，不代表接口基准必然按该幅度变化。
- **同指数价差测算**：比较两个标的当前返回的溢价率。代码仅限制同跟踪指数，尚未强制两者采用相同估值状态或基准日期；解读结果时需关注 IOPV 与公布净值回退的差别。
